# NERC grants data management tracking: Onboarding

## 🌱 Learning objectives

By the end of this session, attendees will be able to:

- Navigate the project board and locate assigned work
- Understand the relationship between Project and Dataset issues
- Progress work through the data management workflow
- Use checklists, metadata fields, labels, and reminders effectively
- Know where to find support and additional documentation

---

# 🗺️ Introduction and system overview (10 mins)

## Objective
Understand what the system is used for and how it fits into the wider data management process.

## Demonstration
Show:
- The GitHub Project board
- The available views
- A Project issue and a Dataset issue
- The links to related systems such as DataMad and Help Scout

Explain:
- A Project represents a grant or other data-generating activity
- A Dataset represents an individual dataset generated by that project
- The system provides a central place to track progress and actions

## Activity
Ask attendees to:
- Open the board
- Locate the My projects view
- Open an example issue

## Key takeaways
- Projects are parent issues
- Datasets are sub-issues
- Most day-to-day work happens within GitHub issues

---

# 👀 Finding and understanding your work (10 mins)

## Objective
Learn how work is organised and how to find assigned projects and datasets.

## Demonstration
Show:
- My projects
- My datasets
- All projects
- All datasets
- Reporting view

Explain:
- Personal views focus on assigned work
- Team views provide operational oversight
- Reporting view supports management reporting and exports

## Activity
Ask attendees to:
- Open an assigned issue
- Identify its type
- Find its current status
- Locate the Sub-issues progress field

## Key takeaways
- Most users primarily work from My projects and My datasets
- Status indicates where work sits in the process
- Projects track progress across multiple datasets

---

# 🎯 Managing workflow progress (15 mins)

## Objective
Learn how issues move through the data management lifecycle.

## Demonstration
Show how to:
- View workflow statuses
- Move an issue between statuses
- Update status from both board and issue views

Walk through:
1. No Status
2. DMP in progress
3. Pre-delivery comms
4. Data due
5. Archiving in progress
6. Archiving completed
7. No archival data
8. Escalate to NERC

## Activity
Ask attendees to:
- Move a training issue to a new status
- Identify what work must be completed before progressing further

## Key takeaways
- Statuses represent stages of the data management lifecycle
- Issues should only move forward when relevant tasks are complete
- Status can be updated from multiple locations

---

# ✅ Using checklists and metadata (10 mins)

## Objective
Understand how work is recorded and tracked within each issue.

## Demonstration
Show:
- The issue checklist
- Metadata fields
- Fields requiring manual input

Demonstrate how to update:
- Status
- Funding stream
- DMP agreed
- Data delivery expected
- Data delivered
- Labels

## Activity
Ask attendees to:
- Check off a completed task
- Update a metadata field
- Review which fields are populated automatically

## Key takeaways
- Checklists act as the primary task-management tool
- Most metadata is automated
- Manual updates should be kept current to support reporting and automation

---

# ⏰ Managing blockers and reminders (10 mins)

## Objective
Learn how to communicate blockers and ensure actions are not missed.

## Demonstration

### Blocker labels
Show how to:
- Apply an On hold label
- Apply an Unresponsive label
- Add an explanatory comment

### Automated reminders
- Annual check-in due
- 6-month check-in due
- End date passed

### Manual reminders
- `/remind [who] [what] [when]`
- e.g.: `/remind me to send the first DMP chase in 6 weeks`

### Notifications
Show where reminder notifications are received.

## Activity
Ask attendees to:
- Add a blocker label to a training issue.
- Create a test reminder.
- Identify where reminder emails will appear.

## Key takeaways
- Labels communicate blockers and trigger workflows
- Automated reminders help keep projects on track
- Custom reminders can be created whenever required

---

# 💬 Wrap up (5 mins)

## Objective
Ensure attendees know where to find help and continue learning after onboarding.

## Demonstration
Show:
- The documentation
- The Data Management Support GitHub Project
- Where to find key information within project issues

## Activity
Quick knowledge check:
- Where do you find assigned work?
- How do you progress an issue?
- When should blocker labels be used?
- How are reminders created and managed?

## Key takeaways
- Use My projects and My datasets as your primary workspace
- Follow checklist tasks before changing status
- Keep metadata current
- Use labels and reminders to manage risk and workload
- Raise support requests through the [Data management support project]()
